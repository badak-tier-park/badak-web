# 맵 관리 — 작업 시 주의

## 맵은 지우지 않는다
맵은 리그 맵 배정·팀배틀·토너먼트가 FK로 참조하고, 전적(`games`)은 **맵 이름 텍스트**로
매칭된다(`games.map_name` ↔ `maps.name`/`aliases`). 그래서
- 래더에서 빠진 맵은 삭제하지 않고 `is_ladder`만 끈다
- 맵 이름을 바꾸거나 버전이 올라가면 **옛 이름을 별칭에 남긴다.** 지우면 그 이름으로
  찍힌 지난 리플레이 전적이 맵에서 떨어져 나간다

## 래더 맵 동기화 (리퀴피디아)
스타 리마스터는 래더 맵 풀을 조회할 공개 API가 없어, 시즌별 맵 풀과 맵 정보가 구조화돼
있는 리퀴피디아(`Maps/Ladder_Maps`)를 출처로 쓴다. 조회는 `api/liquipedia-maps.ts`,
매칭 규칙은 `src/lib/ladderMatch.ts`, 반영은 `src/lib/maps.ts`.

- **자동 반영하지 않고 관리자 검토를 거친다.** 리퀴피디아는 영문명(Fighting Spirit),
  바닥티어는 한글명(투혼)으로 등록돼 있어 그대로 넣으면 같은 맵이 중복 생성된다
- `liquipedia_name`이 다음 동기화 때 같은 맵을 알아보는 키다. 맵당 하나뿐이라 한 맵에
  두 래더 맵을 연결하면 앞의 연결이 사라진다
- `liquipedia_name`은 **래더 맵만의 표시가 아니다.** 맵 등록 화면에서 리퀴피디아 검색으로
  불러온 맵에도 저장된다(나중에 래더에 들어오면 동기화가 자동 연결하도록). 래더 여부는
  `is_ladder`로만 판단한다
- 리퀴피디아 정보 상자는 맵마다 채워진 정도가 다르다 (투혼 페이지엔 크기·타일셋이 없음).
  빈 값은 null로 두고 등록할 때 관리자가 채운다 — 추측해서 채우지 않는다
- 리퀴피디아 이용 규칙: 연락처가 담긴 User-Agent 필수, 요청 간격 2초 이상, `parse`
  액션은 훨씬 엄격하므로 `query` 액션만 쓴다. 브라우저는 User-Agent를 바꿀 수 없어서
  반드시 서버(`api/`)를 거친다
- 리퀴피디아는 커뮤니티 위키라 시즌 교체 직후 며칠은 갱신이 늦을 수 있다
- 모든 리퀴피디아 API 요청은 `politeFetch` 큐를 거친다. 요청 간격 규칙은 동기화·검색이
  동시에 들어와도 지켜져야 해서, 새 요청을 추가할 때도 직접 `fetch`하지 말 것

## 맵 검색 (등록 화면)
- 영문 이름만 걸린다(영어 위키). 부분 입력은 마지막 단어에 `*`를 붙여야 결과가 나온다
- 검색어는 영문·숫자 위주로만 남긴다. 리퀴피디아 검색은 `insource:/정규식/` 같은 특수
  문법을 지원해, 입력을 그대로 넘기면 저쪽 서버에 무거운 쿼리를 던지는 통로가 된다
- 검색 조건 `hastemplate:"Infobox map"`이 없으면 대회·선수 페이지가 섞인다

## 맵 이미지
- **리퀴피디아 맵 이미지는 자유 라이선스가 아니다.** 글은 자유 라이선스지만 이미지는
  `license=Blizzard`이고 리퀴피디아도 공정 이용으로 쓰고 있다. 원출처는 대부분 맵 제작자
  블로그(910map). 그래서 가져올 때 원작자·출처(`image_author`/`image_source`)를 반드시
  같이 저장하고 화면에 표기한다
- 링크로 걸지 않고 우리 저장소에 복사한다 (리퀴피디아 트래픽을 끌어 쓰지 않게, 파일명이
  바뀌어도 안 깨지게)
- 동기화는 **이미지가 없는 맵에만** 넣는다. 관리자가 직접 올린 이미지를 덮어쓰지 않는다
- 관리자가 이미지를 바꾸거나 지우면 원작자 표기도 지운다 — 더 이상 그 이미지가 아니므로
- `image_source`는 위키에서 누구나 편집하는 값이다. href로 쓸 땐 http(s)인지 먼저 확인한다
