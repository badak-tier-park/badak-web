# 화면(UI) 공통 규칙

화면·스타일 작업 시 참고. 루트 CLAUDE.md의 "화면(UI) 공통"이 요약본이다.
공통 파샬의 사용법은 각 파일 머리 주석에 있으니 여기서는 **왜 그렇게 하는지**만 적는다.

## 어디에 무엇이 있나
| 파일 | 역할 | 로드 방식 |
|------|------|-----------|
| `theme.scss` | 색·레이아웃 토큰(`--c-*`, `--page-*`, 티어·종족) | `main.ts`에서 전역 |
| `_tokens.scss` | 티어/종족 칩·배지 클래스 | `main.ts`에서 전역 |
| `_page.scss` | 페이지 제목·뒤로가기 + buttons/modal/layout/table 묶음 | 화면 scss에서 `@use` |
| `_layout.scss` | `page-shell` / `page-content` 믹스인, 브레이크포인트 | `_page` 경유 |
| `_modal.scss` | 모달·폼 필드 | `_page` 경유 또는 직접 |
| `_picker.scss` | 검색+선택 오버레이(맵·선수 고르기) | 필요한 화면에서 직접 |
| `src/style.css` | html/body 기본값만 | `main.ts`에서 전역 |

화면 scss는 scoped라 `@use`한 파샬은 그 컴포넌트 안에서만 적용된다. 자식 컴포넌트(예:
ParticipateView 안의 RankingsTab)는 부모의 공통 클래스를 물려받지 못하므로 필요한 파샬을
따로 `@use` 한다.

## 색
- 테마는 다크 기본 + `[data-theme="light"]`. **OS 다크모드(prefers-color-scheme)를 따르지 않는다.**
  예전 `style.css`의 Vite 템플릿 변수가 OS 설정을 따라가 앱 테마와 어긋났다
- 값을 직접 쓰지 말고 토큰을 쓴다. 다크 값을 박아 두면 라이트에서 그 부분만 다크 톤으로 남는다
  - 브랜드: `--c-brand`, `--c-brand-text`, 투명도 변형은 `rgba(var(--c-brand-rgb), a)`
  - 위험: `--c-danger`, `rgba(var(--c-danger-rgb), a)`
- 초록·노랑·파랑 하드코딩(`#4ade80`, `#fbbf24`, `#60a5fa` 등)은 아직 남아 있다. 티어/종족
  색과 값이 같아 의미(성공? D티어?)를 확인하며 하나씩 바꿔야 해서 일괄 치환하지 않았다
- `--c-surface-raised`는 다크에서 2.5% 흰색이라 **거의 투명**하다. 카드 배경용이지 모달·팝오버
  배경으로 쓰면 뒤가 비친다 — 떠 있는 창은 `--c-surface`

## 레이아웃
- 본문 폭은 3단계뿐: `--page-w-narrow`(760, 폼·단일 목록) / `--page-w`(900) / `--page-w-wide`(1100,
  표·2단). 화면마다 폭이 달라 페이지를 옮길 때 본문이 들쭉날쭉했던 것을 정리한 것이라
  새 화면에서 임의의 px를 쓰지 않는다. 홈(1200)과 지목식(1440, 화면 전체 사용)만 예외
- 여백은 `--page-gutter` / `--page-pad-top` / `--page-pad-bottom`. 휴대폰에서 토큰 값이
  줄어들므로 화면별로 미디어쿼리를 따로 쓸 필요가 없다
- 높이는 `100vh` 다음 줄에 `100dvh`를 함께 쓴다. 모바일 브라우저는 100vh에 주소창 높이를
  포함해 화면 아래가 잘린다
- `#app`에 `text-align: center`가 걸려 있다(역사적 이유). 본문을 왼쪽 정렬해야 하는 화면은
  컨테이너에 `text-align: left`를 직접 준다. 전역에서 빼면 가운데 정렬에 기대는 화면이
  깨지므로 화면을 하나씩 확인하기 전에는 건드리지 않는다

## 컨트롤 높이
- 한 줄에 나란히 놓이는 검색창·툴바 버튼·필터 버튼은 높이를 `--control-h`(36px)로 맞춘다.
  padding으로 키를 정하면 요소마다 높이가 달라 검색창 옆 버튼이 작게 떠 보였다
- 공통 클래스: 검색창 `.search-input`, 주 액션 `.btn-create`, 보조 액션 `.btn-tool`(ghost).
  제목 줄·검색창 옆에 `btn-pill`을 두지 않는다 — 카드·표 안의 작은 액션용이라 높이가 낮다
- 버튼을 `<a>`/RouterLink로 만들면 루트 `line-height: 145%`를 물려받아 `<button>`보다 커진다.
  높이를 고정하고 `line-height: 1`을 준다(`.btn-create`·`.btn-tool`은 처리돼 있다)
- `.search-bar`는 단독으로 쓸 때를 위해 아래 여백(16px)이 있다. 버튼과 한 줄에 둘 때는
  그 여백을 0으로 하고 줄 컨테이너에 여백을 준다 — 남기면 옆 버튼이 검색창보다 위로 뜬다

## 휴대폰(640px 이하)
- 브레이크포인트는 `_layout.scss`의 `$bp-mobile`(640) / `$bp-tablet`(900)만 쓴다
- **모달은 하단 시트**가 된다(`_modal.scss`). 가운데 뜬 작은 창은 키보드에 가려지고 버튼이
  엄지가 닿지 않는 위치에 놓인다. 화면별로 모달을 따로 만들었다면 같은 규칙을 맞춰 준다
  (달력·엔트리 공개 모달이 그렇게 되어 있다)
- 표는 `<div class="table-scroll">`로 감싸고 표에 `min-width`를 준다. 열이 찌그러져 글자가
  세로로 쌓이는 것보다 옆으로 미는 편이 읽기 쉽다
- 헤더는 375px에 출석·알림·테마·로그아웃 + 페이지 액션(`#actions`)이 한 줄에 들어가야 한다.
  닉네임/아바타와 출석 글자를 숨겨 자리를 만든다. `#actions`에 버튼을 넣을 땐 휴대폰에서
  아이콘만 남도록 글자를 `<span>`으로 감싸 숨긴다(리그 참여의 명예의 전당 버튼 참고)
- iOS 홈 화면 앱은 상태바·홈 인디케이터가 화면 위에 겹친다. 화면 끝에 붙는 요소(헤더, 하단 시트,
  하단 토스트)는 `env(safe-area-inset-*)`만큼 여백을 준다
- 드래그 UI는 터치에서 스크롤과 충돌한다. `pointercancel`을 반드시 처리하고(안 하면 끌던
  복제본이 화면에 남는다), 터치에는 탭 → 확인 같은 대체 경로를 둔다(`useDraftDnD`)

## 화면 이동
- 뒤로가기 버튼(`.btn-back`)은 `router.back()` 대신 **상위 화면으로 직접** 이동한다.
  주소로 바로 열거나 새로고침한 뒤, 그리고 브라우저 뒤로가기가 없는 홈 화면 앱에서는
  `back()`이 아무 데도 가지 않거나 사이트 밖으로 나간다
- 화면 머리는 `AppHeader` → `.btn-back` → 제목 순서다(홈만 예외). 제목은 가능하면 `.page-title`

## 선수 표시 (2026-10 리뉴얼)
- 순서는 **닉네임 · 종족 · 티어 · (핸디)**. 컴포넌트 `RaceBadge` / `TierBadge` / `HpBadge`를 쓴다
- **닉네임에 티어색을 칠하지 않는다.** 티어는 글자 칩으로만 보여준다 — 색+실선/점선 테두리로
  +/-를 구분하던 방식은 "이게 무슨 티어야?" 소리가 나올 만큼 읽기 어려워 폐기했다
- 티어 색은 알파벳(S·A·B·C·D·E) 단위이고 +/-는 같은 색이다(`--tier-a-plus` 등은 별칭으로만 남음)
